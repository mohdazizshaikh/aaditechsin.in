## Provider connection and operational workflow

Official [NICSI GeM listings](https://nicsi.nic.in/nicsi/nicsi-gem-bids/), [NICSI active tenders](https://nicsi.nic.in/nicsi/active-tenders/) and [CPPP issuer listing](https://etenders.gov.in/eprocure/app?org=National+Informatics+Centre+Services+Incorporated&page=FrontEndLatestActiveTendersOrgwise&service=page) are public research routes. No machine-readable official feed grant or compatible live endpoint has been confirmed. Third-party structured tender data providers exist but require commercial/rights/format review; no endorsement or account connection. No portal scraping or CAPTCHA bypass.

New private scheduled worker consumes a normalized version-1 tender JSON feed on an explicitly authorized HTTPS endpoint. Existing V10.7M notice contract, including selected_service=null on every incoming item. Empty feed is valid; up to 25 observations per source; 64 KiB JSON application cap (transport existing 256 KiB cap). Feed must preserve issuer reference, actual observed date and deadline and truthful source state. No automatic correction of dates. Provider is responsible for authorized collection and normalization, including amendments. Input source must exactly match reviewed issuer key; a third-party host can supply the authorized normalized feed but does not become the official issuer. No user-defined arbitrary URL input or provider selection of service.

Private config under discovery:
- enabled, tender_review_enabled and tender_poll_enabled explicitly true, growth.enabled true, growth resumed only after acceptance.
- tender_poll_minutes 60–10080, default 1440; at most five distinct active official source keys; archive source not eligible.
- tender_feeds maps source key (e.g. nicsi) to exact fields authorized (true only after approval), host, url (HTTPS, exact host, no query/credentials/port/fragment), services (ordered 1–14 distinct catalog IDs), bearer_token (null for approved unauthenticated feed, or private reviewed token). No real endpoint or token shipped. Example placeholder values in this document are not a working provider.
- Source ID ledger prefix tender-feed- reserved from generic feed execution and local batch.
- Before configuring cron: run `php /PRIVATE/secure/maintenance/tender-poll.php --check` (no network or database); then `--status` (DB advisory only, no network). After isolated acceptance configure authorized cron, e.g. every hour `0 * * * * /usr/bin/php /PRIVATE/secure/maintenance/tender-poll.php --scheduled-run` with private protected logs and reviewed PHP path. Actual fetch cadence controlled by private interval; no installation performed here.

Uses pinned public IPv4/TLS, no redirects/proxy, optional private bearer header, bounded JSON. Admission commits a running ledger row before network request, under growth-control lock; concurrent same-source run refused, recent runs skipped, interrupted running state blocks until existing reviewed recovery procedure. Rechecks pause, source configuration (including token and service preference) and run state after network call. If disabled/changed during call no task import. Config files cannot be locked by this transaction: coordinate edits and stopped workers. Failure returns sanitized result and stops remaining sources. No network fetch while paused at admission; a request already in progress is not cancelled.

For each current eligible listed notice, select first matching service from operator-reviewed service order. This is a review routing choice, not inferred eligibility. Multi-match notices get one research task. Expired, unconfirmed, stale, cancelled, archived, unmatched, deadline-unknown and out-of-scope notices are excluded. One transaction creates pending research tasks and completes ledger counts, or rolls back all task writes. Duplicate existing tasks preserved across repeated polls; changed service preference for an existing reference blocks batch for manual review. Existing task evidence and deadlines are NOT automatically updated or cancelled on amendments; recheck original issuer and manually review. Missing notice is not cancellation. Across-source duplication still requires human review. No leads, outbound delivery, bids, payments, scraping, or automatic approval. Owner /tenders and /task show pending research; /discoveryruns shows run ledger (imported = new research tasks, duplicates = preserved, skipped = excluded notices for tender-feed- IDs).
