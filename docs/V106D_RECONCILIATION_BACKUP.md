## Backup artifact verification

On private POSIX machine, store authorized gzip SQL dump in private directory (no group/other permissions), regular file 0600 or stricter, one hard link, not under repository or public_html. Record SHA256 independently at backup creation and preserve securely. Run python3 workers/backup-verify.py --file /private/backup.sql.gz --sha256 EXPECTED_HASH. Reads compressed bytes and checks SHA256, then validates gzip decompression/CRC to EOF, nonempty stream, bounded 4 GiB compressed and expanded size, file metadata unchanged during read. No content printed, no extracted SQL, no restore or DB access. Does not prove encryption, provenance, SQL validity, completeness, table counts, recovery time or restorability. Encrypt backups independently, test actual isolated restoration with authorized credentials, run schema and data integrity checks, confirm recovery/rollback separately before deployment. Never execute untrusted SQL against production. Synthetic tests exercise digest mismatch, corrupt gzip, size and permissions.
