# V10.7O — customer inquiry response and missed-contact review

## Website inquiry response queue
New private /portal/inquiries.php, reachable from the existing authenticated owner portal. Independent leads.response_queue_enabled defaults OFF, depends on leads, database and portal. Internal response_target_hours integer 1–168, default 24. No customer-facing SLA. Oldest-first list of current new/qualified inquiries, 25 per page, 4 filters (all, target reached, new, qualified), counts, stored inquiry details and suggested response structure. The target is calculated from created_at (assumed UTC as existing reporting), not last contact or proof of a missed response. The owner manually responds via an authorized channel and explicitly records that response; POST requires the existing secure admin session, CSRF, checked confirmation, expected status and updated_at. Atomic status update and owner audit; stale status/time or replay refused. Existing lead status controls remain available in the main portal; this is not a full communication history or delivery verification. Existing status can be changed there, including reopening a lead. No new personal data collected, exported or sent. No automatic email/SMS/WhatsApp/calls or contact sharing. Owner Telegram /inquiryqueue and daily /today /leads report counts only, no contact, reference, message or lead ID. Owner must review actual response and consent before contacting. Use portal HTTPS, existing admin fingerprint/timeout, owner authentication/TOTP, no-store/noindex. Verify access with partner, logged-out, stale session and owner in staging; confirm actual customer response and status retention.

## Automatic internal aggregate review
New private communication-auto-review.php worker: --check validates flags/lookback without DB/network; --plan reads eligible aggregates and rolls back; --scheduled-run creates missing internal reminders in one transaction under growth-control lock, only if growth/communications/reviews/auto_review_enabled true and growth resumed. Lookback integer 1–30 completed UTC days, default 7. Positive missed_count only, all four channels (email, WhatsApp, SMS, calls), up to 120 daily/channel rows. Due today UTC. Existing open/completed/cancelled reminders preserved unchanged; repeated runs idempotent, no automatic reopen or rescheduling. No provider retrieval, individual missed contact detection or new data collection. A missed aggregate is not a list of people. Review via existing /commreviews and /completecommreview or /cancelcommreview. Existing aggregate import/retention rules remain applicable. Optional owner-configured cron after acceptance (e.g. hourly private PHP CLI); not installed. No direct outbound message or notification delivery.
