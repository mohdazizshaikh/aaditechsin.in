# V10.2G OAuth credential lifecycle and connection health

Source only. Seven OAuth platforms: Facebook, Threads, LinkedIn, X, Google Business Profile, Instagram and YouTube. Telegram bot tokens are separate and not OAuth. No authorization callback, token exchange, refresh-token storage, automatic renewal or provider revocation API implemented. Provider-issued credentials remain only in private config. LinkedIn programmatic refresh is restricted to eligible apps; Google refresh/revocation can have broader consent effects. References: https://developers.google.com/identity/protocols/oauth2/web-server , https://learn.microsoft.com/en-us/linkedin/shared/authentication/programmatic-refresh-tokens , https://developers.facebook.com/docs/facebook-login/guides/access-tokens/debugging .

Apply V10.2G after V10.2F. oauth_lifecycle.enabled defaults false for backward-compatible source testing; mandatory true before live social activation. When enabled, each provider requires a unique 32 lowercase hex generation label (random non-secret identifier, regenerated for every credential/scope/account change) and strict UTC expires_utc (provider expiry or earlier owner review deadline for no-expiry token); revoked=true blocks local use. Missing/invalid metadata, expiration and <=10 minutes remaining fail closed in all existing OAuth target resolvers; <=7 days reports renew_soon. This is locally declared expiry, not provider token introspection. Existing in-flight work cannot be recalled. Do not switch off enforcement to bypass expiry.

Manual rotation: pause growth, stop workers and transfers, disable provider flag, reconcile uncertain operations; obtain replacement through official provider authorization console using least scopes, update private config atomically with new token/generation/expiry (0600), no token in Git/logs/Telegram/CLI arguments. Confirm correct account and use private CLI --check after enabling only on isolated staging while paused. Revoke old credential through provider console if safe, verify old access invalid, then resume only after explicit owner approval. For a suspected leak disable/revoke immediately and reconcile, not just set local revoked flag. No app secrets or refresh tokens in DB.

php secure/maintenance/oauth-health.php --status is local sanitized report. --check PROVIDER makes one bounded read-only identity/access check using existing fixed-host adapters; no publication or write test. For GBP this checks location access only, not identity or publishing permission. Records latest state, target label, non-secret generation, UTC check time; no tokens, raw errors or provider payloads. /connections provides owner status; evidence becomes stale after 24h or generation/target change. Health does not itself authorize publishing and is not a blocking freshness requirement. No scheduled probes, no automatic token renewal. Maintain manual renewal reminders and provider authorization. No credentials requested or real checks performed in CI.
