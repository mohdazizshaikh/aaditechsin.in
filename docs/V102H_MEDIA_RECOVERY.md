# V10.2H intermediate network image receipts

Source-only change to existing default-OFF LinkedIn and X image workflows. Apply after V10.2G. The production worker now commits a sanitized LinkedIn image URN immediately after initialization and records upload success before reading readiness. X media ID is committed after validated upload response and before identity recheck/post. Each receipt is bound to an in-flight local publication and provider, with one-way initialized-to-uploaded transition. If persisting the receipt fails, no further provider operation occurs. No signed URLs, token, raw payload or credentials stored. /mediarecovery shows the ten latest uncertain/sending rows and resource evidence. Read-only, no automatic retry, no automatic reconciliation or resume. Crash before receipt commit can still leave no known resource ID. Manual inspection in authorized provider interface required. This does not implement LinkedIn/X/Threads video or carousel publishing. Official LinkedIn Videos API multipart and signed-URL requirements reviewed: https://learn.microsoft.com/en-us/linkedin/marketing/community-management/shares/videos-api . These remain separately tracked, along with automatic private transfer, OAuth renewal/alerts and actual provider acceptance. No production changes.
