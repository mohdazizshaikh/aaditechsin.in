# V10.2E Threads and Instagram single JPEG source phase

Official references: https://www.postman.com/meta/threads/request/34203612-c5844b32-22e8-4c0c-9564-2694cede8304 and https://developers.facebook.com/docs/graph-api/reference/shadow-ig-user/media/ . Both provider flows require a fetchable image URL. This endpoint is a short-lived bearer capability, NOT provider-authenticated: anyone with the URL can fetch approved bytes during its lifetime. Only approved non-sensitive public marketing content may use it. Never expose customer files. Require staging HTTPS, access-log query redaction or disabled logging for this route (including CDN/proxy), no caching, no referrer forwarding, no URL in Telegram or stdout, restricted DB and filesystem. If log redaction cannot be confirmed, leave fetch_enabled OFF. Provider may retain copies. No actual provider fetch or post tested.

Apply migration after V10.2D. Flags media_upload.fetch_enabled, threads_images_enabled and instagram_images_enabled default OFF. Existing social/meta or linked IG account flags, verified public_base_url HTTPS origin and 0700 private_root required. Convert approved PNG privately to RGB JPEG at same dimensions using Pillow; e.g. Image.open('creative.png').convert('RGB').save('creative.jpg',quality=90). No automatic proof of derivation: owner independently reviews exact JPEG, which has its own hash. CLI --stage PROVIDER TASK REV MANIFEST_SHA256 /private/creative.png /private/creative.jpg verifies approved PNG hash and JPEG profile and stores JPEG hash; 8 MB cap. /metaimages, /metaimage ID, /approveimage ID JPEG_SHA256 PROVIDER ACCOUNT_ID, /cancelimage ID. Separate approval authorizes public post and temporary fetch. Worker --check-target PROVIDER, --create PROVIDER ID generates 256-bit bearer, stores digest only, 15-minute expiry, 20 GET/HEAD requests max, exact hash/size/dimensions, current approved state and pause. No Range support. --status PROVIDER ID is read-only; --publish PROVIDER ID requires FINISHED, revokes fetch token, claims once, then rechecks and publishes. Cancel revokes bearer, not provider copy. No retries, no URL refresh, no cron, no automatic cleanup. Crash or expiry requires manual reconciliation. Threads text/image and Instagram Reel/image mutually exclusive per revision. /publications includes all ledgers.
