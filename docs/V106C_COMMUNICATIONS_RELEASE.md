## Authorized aggregate connector contract

The source is a trusted business-owned or contracted aggregate reporting service, NOT a native WhatsApp Cloud API, SMS vendor or telephony API adapter. Obtain authorization and confirm definitions for received/answered/missed (mutually exclusive answered/missed from same source and day). No individual messages, customer identifiers, phone numbers, recordings or credentials are accepted in the payload. Configure communications.bridge_enabled and one explicit communications.bridges.whatsapp/sms/calls source enabled+authorized with exact HTTPS URL/host, independent 32-byte random HMAC key encoded as 64 lowercase hex, private bearer token (32–256 safe characters), random non-secret 32-hex generation. Change generation and credentials when source changes. URL cannot include userinfo, query, port or fragment. Pin one public IPv4 after checking all DNS answers; no redirect, proxy or private destination. GET only, 15-second timeout, 8 KiB response cap, application/json required. Source must return a signed envelope with exact keys payload_b64 and signature. Decode canonical base64 (max 2048 bytes), verify lowercase hex HMAC-SHA256 over the ASCII domain separator "aaditechs-communications-v1" followed by one LF and exact decoded UTF-8 JSON bytes, using the raw 32-byte key. Exact payload keys: version=1, generation, generated_utc (YYYY-MM-DDTHH:MM:SSZ), channel, day_utc, received, answered, missed. The channel and generation must match private config, day must be yesterday UTC, generated time must be at/after today's UTC midnight, no more than 24 hours old or five minutes in future. Existing count validation applies; no extra fields. A valid signature authenticates the configured source, not the truth of its figures.

Exact duplicate is no-op; conflicting counts blocked, audit only on new imports. No automated retries, scheduler, polling loop, customer reply, provider-account access, raw payload storage or logs.
