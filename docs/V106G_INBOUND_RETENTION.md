## Native Twilio inbound callbacks

Independent communications.twilio_inbound.sms and calls configurations require enabled, authorized, log_redaction_verified and parent growth/communications flags. Use an authorized dedicated business subaccount, exact AC SID, E.164 destination, private account Auth Token (not restricted API key, which is for usage reads), independent stable 64-hex dedupe key and exact HTTPS callback URL with no query, explicit port or redirect. Use /api/twilio-sms-inbound.php for SMS and /api/twilio-voice-inbound.php for terminal inbound voice status callbacks only. Never set the voice endpoint as the call-control/TwiML routing URL. SMS webhook returns empty TwiML (no reply); replacing an existing SMS webhook can disrupt existing routing, so review coexistence before connecting. Voice status callback returns 204 without call-control instructions.

POST application/x-www-form-urlencoded, max 64 KiB and 100 fields, strict single-value form decoding, duplicate keys/invalid encoding rejected. Verify provider X-Twilio-Signature using configured exact HTTPS URL and sorted decoded parameter names/values, base64 HMAC-SHA1 with private Auth Token (provider-defined algorithm). Never trust forwarded URL headers. Exact account/destination, SMS MessageSid SM prefix, SmsStatus received, E.164 sender, NumMedia=0; MMS, WhatsApp and other senders excluded. Voice accepts inbound Direction, CallSid CA prefix and terminal completed/busy/failed/no-answer/canceled only. Provider callback variants must be validated before activation. No call routing changes, recording, outbound send, or message detail persistence. Invalid requests 404, paused/database/cap failure 503. Actual retry behavior must be verified.

Store only stable HMAC event digest, account/destination/channel hash, channel and first receipt UTC day. Raw form may transiently include message body, phone numbers and other personal data; no deliberate logging, persistence or response echo. Disable request/query/body/error logging at hosting/CDN/APM layers, require rate limits and privacy/retention approval. Pseudonymous hashes remain protected data. /twinbound, /intelligence, owner report and dashboard show previous UTC receipt day counts; missing is not zero coverage, not provider event time, not unique callers, answered or missed calls. Dedup remains across receipt days. Classic signed forms do not establish reliable event freshness (SMS lacks timestamp); a captured valid request can replay if its digest is deleted or key changes. Retain dedupe rows for now, cap 50,000 across channels, block rather than silently purge. A replay-safe retention and credential rotation procedure is required before sustained use, and separate authorization is required for any actual provider routing/subscription. No automatic purge of Twilio digests.

Provider references: https://www.twilio.com/docs/usage/security ; https://www.twilio.com/docs/usage/webhooks/messaging-webhooks ; https://www.twilio.com/docs/usage/webhooks/voice-webhooks .
