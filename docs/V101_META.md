# V10.1 Meta publication — limited text-only source phase

Facebook Page feed and Threads text publishing are separate approved-destination adapters. Instagram is deliberately not enabled: media must be authorized and transferred securely; V9.8 local-only manifests are not uploadable assets. No real account connected or post sent by CI.

Official references checked 24 Nov 2026: https://developers.facebook.com/docs/graph-api/reference/page/feed/ (Page access token, CREATE_CONTENT role, pages_manage_posts, pages_read_engagement, pages_show_list); https://www.postman.com/meta/threads/collection/dht3nzz/threads-api (Threads account authorization, threads_basic and threads_content_publish, text container followed by threads_publish); https://www.postman.com/meta/instagram/documentation/6yqw8pt/instagram-api (professional accounts and media publishing). Check exact API version, scopes, app review/access level and provider contracts before live use.

## Staging setup
Back up isolated staging and apply V10.1 after V10.0. Configure private social.meta.enabled and individual facebook/threads flags only after app/account authorization, with growth, creative and social enabled. Default OFF; choose actual provider-supported API version explicitly. Obtain Page/Threads token via official OAuth tools or authorized app flow (not implemented here); never store in Git, URLs, logs or chat. Distinct tokens and explicit numeric account IDs. Run private CLI php secure/maintenance/meta-worker.php --check-target facebook (or threads) to confirm /me identity. Identity does not prove publish scope. No Instagram worker or configuration token yet.

Create and approve a matching channel creative task in private owner bot. /metatarget displays configured IDs only. /metaschedule facebook TASK REV ACCOUNT_ID YYYY-MM-DDTHH:MMZ queues current approved revision within 30 days; /meta lists ledger, /metacancel ID cancels only queued entries. Run php secure/maintenance/meta-worker.php --run facebook (or threads) explicitly on approved test account; one due item per invocation. No automatic schedule installed. Verify identity again before any POST. API acceptance is not reach or independently verified visibility.

No retries of POST. Threads container creation explicitly disables auto-publish and uses returned creation ID for publish. A failed/malformed/ambiguous response is not requeued; process death can leave sending. Reconcile manually against actual provider account before any fresh task. No delete or retry endpoint. Pause blocks claims; cannot revoke an in-flight claimed send, so stop cron and wait for workers before changing credentials/target or emergency pause. Cancel queued posts before disabling config. HTTPS fixed hosts, bearer header, no redirects, no proxies, bounded response and timeout. No raw provider errors or credentials persisted.
